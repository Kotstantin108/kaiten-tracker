# Задачи проекта

Задачи живут не в репозитории кода: их показывает и ведёт команда `kaiten`.
Запускайте её из репозитория, над которым работаете, — она сама знает проект и
продукт. Флаги и примеры — `kaiten <команда> --help`.

Отказ команды — это ответ, а не помеха. Если `kaiten` отказал (репозиторий не
подключён, задачу не взять в работу, изменение не применено или не
отправлено), передайте причину человеку и остановите работу по задаче: код,
ветки и отметки ждут его решения.

## Найти задачу

Работа над кодом начинается с задачи — в том числе когда человек описал её
словами, без ключа.

- `kaiten search <слова>` — по заголовку, «Сути», постановке и журналу, в
  открытых и закрытых. Подходит задача, в которой есть все слова; окончания
  русских слов не важны. Варианты одного слова — через «|»:
  `kaiten search "онбординг|onboarding" экран`. Ноль находок — повторите с
  одним самым редким словом, затем посмотрите `kaiten list`.
- `kaiten search --regex "<выражение>"` — как grep: `"лимит.*месяц"`.
  `--lines` показывает все совпавшие строки задачи, `--context 2` — с
  соседними.
- `kaiten list` — открытые задачи этого продукта; `--all` — весь проект;
  `--status in-progress` — что сейчас в работе.
- Закрытые задачи — история решений: ищите в них, прежде чем предлагать то,
  что уже обсуждали, и когда нужно понять, как делали модуль.

Человек говорит «продолжаем …» — найдите задачу, затем прочитайте, где
остановились: `kaiten show <задача> --log 3` и вложения (`kaiten files`).

Готово, когда исход один из трёх: задача одна — работайте по ней; подходящих
несколько — спросите человека, какая; задачи нет — скажите об этом человеку и
спросите, завести её или сделать без задачи.

Задачу называйте ключом из первого столбца списка: его понимают все команды.

## Перед работой над задачей

1. `kaiten pull` — свежие задачи. Готово, когда команда написала «обновлены»
   или «уже свежие».
2. `kaiten show <задача>` — задача целиком. Большую (эпик) читайте по
   частям: `--outline` — оглавление, `--section "<название>"` — раздел,
   `--todo` — неотмеченные пункты. Готово, когда вы можете назвать:
   - пункты, по которым задача считается сделанной;
   - её статус в первой строке под заголовком. В работу берут из `ready`
     («Готово к работе»), `blocked` и `review`; задачу `in-progress`
     продолжают. Из `inbox` и `backlog` задачу переводит человек при разборе
     — сообщите ему и ждите;
   - её эпик и соседние задачи, если в выводе есть строка «Эпик»: они
     подскажут, что уже сделано рядом и чего здесь делать не нужно. Строки
     нет — эпика нет;
   - вложения, если есть строка «Вложения»: `kaiten files <задача> <файл>`.
3. Задаче нужно внешнее — ключ доступа, ответ человека, чужой сервис?
   Проверьте, что оно есть. Нет — `kaiten block <задача> --reason "<чего не
   хватает и у кого это взять>"` и повторите причину человеку в ответе.
4. `kaiten start <задача>` — задача «В работе», и вы на её ветке. Готово,
   когда команда назвала ветку; все коммиты по задаче — в неё.

## По ходу работы

Задачу ведите сразу, а не в конце:

- Пункт сделан и проверен — `kaiten check <задача> '<слова пункта>'`.
  Достаточно нескольких слов, по которым пункт находится однозначно; несколько
  пунктов — одной командой: `kaiten check PRJ-123 'тест на таймаут' 'ретраи'`.
  Одинарные кавычки: в двойных оболочка исполнит текст в обратных кавычках;
  сами обратные кавычки пункта можно не писать. Готово, когда команда назвала
  отмеченные пункты и строка «Пункты» в её ответе показывает нужный счёт.
- Причина дефекта, принятое решение, что проверено и чем, ветка и коммит —
  `kaiten log <задача> "<что>"`. У сделанной задачи в журнале есть хотя бы
  одна ваша запись.
- Отчёт, передача дел, схема, данные по задаче — вложением:
  `kaiten attach <задача> <файл>` или
  `kaiten attach <задача> HANDOFF.md --stdin <<'EOF' … EOF`. Файл с тем же
  именем заменяется. В репозиторий кода такие файлы не кладите.
- Работа упёрлась во внешнее — `kaiten block`, как в шаге 3; ветку оставьте.
- Нашлась отдельная работа — сначала `kaiten search`; задачи на неё нет —
  `kaiten new "<заголовок с глагола>" --type <тип> --agent --summary "<Суть>"`.
  «Суть» — 1–3 предложения для фаундера обычными словами.
- Постановку поправить — возьмите текст из `kaiten show <задача> --raw` и
  передайте исправленный целиком, вместе с шапкой:
  `kaiten edit <задача> --stdin <<'EOF' … EOF`.

Приоритет, исполнитель и сроки — дело людей.

## Сдать работу

`kaiten review <задача> --note "<ветка и коммит, или ссылка на PR>"` — когда
код закоммичен в ветке задачи, проверки проекта прошли, пункты отмечены и
журнал записан. PR открывайте, если так принято в проекте или просил человек;
`review` его не ждёт.

Спайк сдаётся так же, только вместо кода — заполненный раздел «Ответ»
(`kaiten edit`).

На `review` ваша работа заканчивается. `kaiten done` делает человек, который
вливает в прод.
