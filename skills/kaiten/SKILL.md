# Задачи проекта

Задачи живут не в репозитории кода: их показывает и ведёт команда `kaiten`.
Запускайте её из репозитория, над которым работаете. Флаги и примеры —
`kaiten <команда> --help`; задачу называйте ключом из первого столбца списка.

Отказ команды — это ответ, а не помеха. Отказ подсказывает, как исправить
вызов (флаг, текст, раздел) — исправьте и повторите. Отказ по существу
(репозиторий не подключён, задачу не взять в работу, изменение не применено)
— передайте причину человеку и остановите работу по задаче: код, ветки и
отметки ждут его решения. Похоже на настройку машины — `kaiten doctor`.

## Найти задачу

Работа над кодом начинается с задачи — и когда человек описал её словами.
Сначала `kaiten pull`, затем `kaiten search <слова>` (открытые и закрытые
задачи) или `kaiten list`. Закрытые задачи — история решений: ищите в них,
прежде чем предлагать то, что уже обсуждали. «Продолжаем …» — найдите задачу
и прочитайте, где остановились: `kaiten show <задача> --log 3` и вложения.

Готово, когда исход один из трёх: задача одна — работайте по ней; подходящих
несколько — спросите человека, какая; задачи нет — скажите об этом человеку и
спросите, завести её или сделать без задачи.

## Перед работой

1. `kaiten show <задача>`. Готово, когда вы можете назвать пункты, по которым
   задача считается сделанной; статус; эпик и соседние задачи, если есть
   строка «Эпик» (что сделано рядом и чего здесь делать не нужно); вложения,
   если есть строка «Вложения» (`kaiten files`).
2. Задаче нужно внешнее — ключ доступа, ответ человека, чужой сервис — и его
   нет: `kaiten block <задача> --reason "<чего не хватает и у кого взять>"`,
   причину — человеку.
3. `kaiten start <задача>` — задача «В работе», вы на её ветке; все коммиты по
   задаче — в неё. `--assigned` — только если человек прямо поручил именно
   эту задачу («сделай задачу N»); иначе отказ `start` — человеку.

## По ходу работы

Задачу ведите сразу, а не в конце:

- Пункт сделан и проверен — `kaiten check <задача> '<слова пункта>'`.
- Причина дефекта, решение, что проверено и чем, ветка и коммит —
  `kaiten log <задача> "<что>"`. У сделанной задачи в журнале есть ваша запись.
- Отчёт, передача дел, схема, данные — `kaiten attach`, не в репозиторий кода.
- Работа упёрлась во внешнее — `kaiten block`, ветку оставьте.
- В задаче — то, без чего не выполнить её критерии; всё остальное, даже в тех
  же файлах, — вне задачи. Постановка неполна или спорит с кодом — запишите
  это в журнал и спросите человека, а не додумывайте.
- Заметили дефект или работу вне этой задачи и здесь её не делаете — каждый
  раз, без порога «мелочь»: `kaiten search`; задачи нет — `kaiten new ...
  --agent --from <задача> --stdin` с постановкой: что видели, как
  воспроизвести, по чему проверить (`kaiten new --help`). Готово, когда в
  ответе человеку назван ключ найденной или заведённой задачи.
- Постановку поправить — `kaiten edit <задача> --stdin` (текст —
  `kaiten show <задача> --raw`).

Приоритет, исполнитель и сроки — дело людей.

## Сдать работу

Коммит в ветке задачи → проверки проекта прошли → пункты критериев отмечены
→ запись в журнал → `kaiten review <задача> --note "<ветка и коммит, или
ссылка на PR>"`. Пушить ли ветку и открывать ли PR — по правилам проекта в
`CLAUDE.md`. После `review` оставайтесь на ветке задачи. Спайк сдаётся так
же, вместо кода — заполненный раздел «Ответ» (`kaiten edit`).

На `review` ваша работа заканчивается: `kaiten done` делает человек, который
вливает в прод.
