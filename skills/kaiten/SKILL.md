# Задачи проекта

Задачи живут не в репозитории кода: их показывает команда `kaiten`. Запускайте
её из репозитория, над которым работаете, — она сама знает проект и продукт.
Если `kaiten` отвечает, что репозиторий не подключён, — скажите об этом
человеку, который вас запустил, и не ищите задачи другим путём.

## Перед работой над задачей

1. `kaiten pull` — получить свежие задачи. Готово, когда команда написала
   «обновлены» или «уже свежие».
2. `kaiten show <задача>` — прочитать задачу целиком: «Суть», постановку,
   пункты, журнал. Готово, когда вы можете назвать, по каким пунктам задача
   считается сделанной.
3. Если у задачи есть эпик — прочитайте в том же выводе его название и соседние
   задачи: они подскажут, что уже сделано рядом и чего в этой задаче делать не
   нужно.
4. `kaiten start <задача>` — ветка задачи в этом репозитории. Готово, когда
   команда назвала ветку. Если ответила, что задачу не взять в работу, —
   передайте причину человеку, ветку руками не заводите.
5. Коммиты — с `#<номер карточки>`, как подсказал `kaiten start`; ветку
   отправьте на GitHub (`git push -u origin <ветка>`), когда будет что
   показать.

## Найти задачу

- `kaiten list` — открытые задачи этого продукта; `--all` — весь проект.
- `kaiten search <слова>` — по словам, в открытых и закрытых. Закрытые задачи —
  это история решений: ищите в них, прежде чем предлагать то, что уже
  обсуждали.
- Задачу называйте тем ключом, что стоит в первом столбце списка: его понимают
  все команды.
- Вложения задачи (отчёты, схемы) — `kaiten files <задача>`; ссылки в тексте
  задачи уже записаны этими командами.

Флаги и примеры — `kaiten <команда> --help`.

## По ходу работы

Задачу ведите командами `kaiten` — сразу, а не в конце:

- Сделан пункт — `kaiten check <задача> "<пункт>"`: отмечайте только
  проверенное.
- Выяснилось важное, принято решение, что-то мешает —
  `kaiten log <задача> "<что>"`.
- Работа упёрлась во внешнее (доступ, ответ человека) —
  `kaiten block <задача> --reason "<что мешает>"`.
- Нашлась отдельная работа, которой нет в задачах, — `kaiten new … --agent`
  с «Сутью» для фаундера: 1–3 предложения без терминов кода.
- Постановку поправить — возьмите текст из `kaiten show <задача> --raw` и
  передайте исправленный целиком прямо в команду:
  `kaiten edit <задача> --stdin <<'EOF' … EOF`.

Статусы «В работе», «Ревью» и «Сделано» ставятся сами — веткой задачи на
GitHub, PR и merge.
Приоритет, исполнитель и сроки — дело людей. Если `kaiten` сообщил, что
изменение не применено или не отправлено, — скажите об этом человеку.
