# «Было / Стало»

Статус: сделано 23.10.2026, решения согласованы с владельцем 22–23.10.2026.

Цель — по карточке на ревью видно, как изменился экран, без запуска кода.
Визуализация не критична: пропущенная — не авария, а повод вернуть задачу.

## Что это

Скриншоты экрана до задачи и после неё — вложения задачи в папке
`было-стало/`. Они лежат в git репозитория задач и уходят файлами в карточку
Kaiten. В разделе «Файлы» карточки у png видна миниатюра, по клику —
встроенный просмотрщик со стрелками между файлами, а не скачивание (проверено
27.10.2026; прямая ссылка файла при этом отдаёт `Content-Disposition:
attachment`). Ответ исполнителя — поле карточки «Было / Стало»:

- «Есть» — картинки приложены;
- «Нет визуальных изменений» — `--no-visual` с причиной (логика, БД, n8n);
- пусто — ответа ещё нет.

Поле выводят `kaiten review` и `kaiten done` из вложений или из флага, ответ
лежит в шапке задачи (`visual: yes | no`), причина — в журнале,
синхронизация переносит ответ в карточку. Нет ответа в задаче — синхронизация
поле не трогает: задаче, закрытой мимо `kaiten`, его можно поставить руками в
Kaiten.

Почему не ссылка на страницу. Артефакт claude.ai принадлежит учётной записи
разработчика: удалил, ушёл из команды, забыл открыть доступ — ссылка в
карточке мёртвая. HTML-вложение Kaiten отдаёт с `Content-Disposition:
attachment` (проверено 22.10.2026 на jpg, md, js) — его надо скачивать.
Картинки живут вместе с задачей. Страницу или артефакт можно дать ссылкой в
комментарии — дополнением, а не ответом.

## Картинки

- Имена — парами: `было-<экран>.png` и `стало-<экран>.png`; регистр и
  расширение не важны. Одно `стало-` — новый экран. Одно `было-` — отказ:
  убрали, а что стало, не показали.
- png или jpg, до 1 МБ (прочие вложения — до 5 МБ): картинки остаются в git
  навсегда, а репозиторий задач каждый загружает целиком. webp не принимаем:
  просмотрщик Kaiten проверен только на png.
- До 10 экранов на задачу. `kaiten attach` отказывает на 11-м экране сразу, до
  записи (переснятый экран и вторая половина пары — не новый экран), а не
  `review` после 40 приложенных картинок (так было 06.11.2026).
- `kaiten attach` кладёт `было-…`/`стало-…` в `было-стало/` сам. Повтор с тем
  же именем заменяет файл и в задаче, и в карточке.
- `kaiten detach <задача> <картинка>...` убирает лишнее из `было-стало/`
  (экраны сверх предела, повторы, не те файлы) и картинки `было-…`/`стало-…`,
  приложенные мимо папки через `--as`. Отказы `review` называют эту команду.
  Имя без папки — сначала файл с этим именем вне папки, потом из папки:
  09.11.2026 `detach было-x.png` убрал правильную копию из папки вместо
  лишней в корне. Сверка убирает из карточки файлы `было-стало/…`, которых
  нет в задаче: папку с путём в имени создаёт только доставка, человек в
  интерфейсе так файл не назовёт. Картинка мимо папки в карточке остаётся —
  её не отличить от приложенной человеком; прочие вложения `detach` не
  убирает.
- Как снимать — в скилле `kaiten` (раздел «Было / Стало»): исполнитель со
  своим агентом, локально, ширина 390 и 1440 px, «было» — сразу после
  `kaiten start`. Команды для съёмки нет: сделаем, если агенты будут снимать
  плохо или по-разному.

## Где спрашивается

- Типы `story`, `tech`, `bug`; у `epic` и `spike` — нет.
- Проект с блоком `kaiten.visual` и id поля в маппинге (`setup`). Блок без id —
  не спрашивается ничего (`kaiten doctor` и сухой прогон синхронизации
  предупреждают).
- `kaiten review` отказывает без картинок и без `--no-visual`; `kaiten done`
  повторяет проверку, если на ревью ответа не дали. Ответ, уже записанный в
  задаче, повторно не спрашивается.
- Честность ответа проверяет ревьюер: `--no-visual` по изменённым файлам
  интерфейса не отклоняется (владелец: визуализация не критична).
- Карточку перенесли на ревью или в «Сделано» руками в Kaiten — синхронизация
  не запрещает, а называет её в отчёте владельца (`pnpm run kaiten-sync`):
  задачи без ответа ни в задаче, ни в карточке, перенесённые в колонку не
  раньше `kaiten.visual.since`. Отчёт — по состоянию, а не по переходу:
  переход мог зеркалить в файл чужой фоновый проход. Убрать задачу из отчёта —
  поставить поле в Kaiten руками.
- Включение ничего не пишет в карточки: у задач ещё нет ответа.

## Включение

1. Выпустить `kaiten` с `SYNC_VERSION` 3 и прогнать `pnpm run kaiten-sync
   --apply` по каждому проекту: версия в задачах остановит и обновит старые
   копии раньше, чем в задачах появится незнакомый им ключ `visual`.
2. `"visual": { "since": "<дата>" }` в `kaiten` блоке `kaiten.json`.
3. `pnpm run setup --tasks <папка>` — сухой прогон: поле «Было / Стало» с
   вариантами «Есть» и «Нет визуальных изменений», необязательное в Story,
   Tech, Bug. После «да» — `--apply`, id в маппинг; отправить `kaiten.json`.
4. Сухой прогон синхронизации — правок полей карточек быть не должно: у всех
   задач ответа ещё нет.
5. Копия скилла в репозиториях кода — `pnpm run connect-repo` по каждому
   (`kaiten doctor` называет устаревшую): без неё агент не знает, как снимать.
6. Одна пробная задача через `attach` и `review` с синхронизацией — открыть
   карточку и убедиться, что картинки смотрятся по клику.
