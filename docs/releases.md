# Журнал выкаток

Решения согласованы с владельцем 19.11.2026. Код — `src/core/release.ts`
(чистая часть: формат, разбор ввода, версии, «что не записано»),
`src/kaiten-release.ts` (команда, git репозитория кода, страница Kaiten,
сверка).

## Зачем

Когда метрика сдвинулась, нужно быстро ответить, что в этот день вышло в прод.
Журнал — одна страница Kaiten, куда после каждой выкатки попадают строки в
одном и том же виде. Её читает дашборд: инструмент, которым он строится,
доступа к git не имеет, поэтому хранилище — страница, а не файл в репозитории.

Записываются только выкатки в прод. Что не выкатка кода — правки содержимого
в админке, запуск рекламы, выход страниц по расписанию — в журнал не
попадает: это известные слепые зоны.

## Страница

Одна плоская таблица, строка на одно изменение, поля выкатки повторяются в
каждой строке, новые сверху. Все репозитории проекта пишут в одну таблицу.

| Время (МСК) | Поверхность | Версия | Событие | Зона | Тип | Задача | Что изменилось |
|---|---|---|---|---|---|---|---|
| 2026-11-10T18:42+03:00 | продукт | v1.4.0 | релиз | пейволл | изменение | PRJ-123 | Цена годового тарифа видна до оплаты |
| ≈2026-11-02T11:05+03:00 | лендинг | 2026.11.02.1 | релиз | главная | новое | — | Новый первый экран |
| 2026-11-10T19:30+03:00 | продукт | v1.4.0 | откат | — | — | — | Не проходит оплата картой |

- **Время** — по Москве, до минуты, ISO 8601. `≈` перед временем — запись
  сделана позже выкатки, время взято из коммита.
- **Поверхность** — что выкатили: у каждого репозитория кода своя
  (`repos[].release.surface`).
- **Событие** — `релиз` или `откат`. Откат — отдельная строка: версия — та,
  которую откатили, в последней колонке — причина, зона, тип и задача пусты.
- **Зона** и **Тип** — только слова из словарей проекта. Слово не из словаря —
  отказ до записи: иначе «пейволл», «paywall» и «оплата» разойдутся по трём
  группам.
- **Задача** — ключ задачи, как его показывает `kaiten`; `—` — изменение без
  задачи.

Перед таблицей — одна строка-пометка «не править руками». Больше на странице
ничего нет, и это проверяется перед каждой записью.

## Настройка проекта

В `kaiten.json` репозитория задач:

```json
{
  "releases": {
    "page": "<uid документа Kaiten>",
    "zones": ["пейволл", "онбординг", "главная", "прочее"],
    "types": ["новое", "изменение", "исправление", "контент", "техническое"]
  },
  "repos": [
    { "name": "acme-app", "label": "Acme-app", "release": { "surface": "продукт", "versions": "tags" } },
    { "name": "acme-landing", "label": "Acme-landing", "release": { "surface": "лендинг", "versions": "calendar" } }
  ]
}
```

- `releases.page` — uid документа из его адреса. Документ создаёт владелец в
  интерфейсе Kaiten, пустым; первую запись и шапку таблицы делает команда.
  Папку лучше взять такую, где агенты людей (агентский сервер) могут только
  читать, то есть без страницы правил.
- `repos[].release.versions`:
  - `tags` — у выкаток уже есть теги версий. Выкатка — тег `v1.2.3`,
    достижимый из ветки прода. Начало имени тега — `tagPrefix` (по умолчанию
    `v`). Коммиты ветки прода без тега версии выкатками не считаются.
  - `calendar` — версий нет. Выкатка — коммит самой ветки прода (по первому
    родителю: один merge в ветку — одна выкатка). Версию `2026.11.19.1` — день
    выкатки по Москве и её номер за день — выдаёт запись.
- `repos[].release.branch` — ветка, из которой собирается прод (по умолчанию
  `production`).

Нет блока `releases` — нет ни команды, ни сверки. Репозиторий без `release`
в журнал не пишет и сверкой не проверяется.

## Запись

`kaiten release` запускают из репозитория, который выкатили, после пуша в
ветку прода — когда убедились, что прод обновился. Сам пуш команда не делает.

1. Без флагов — каркас: поверхность, версия, коммит, время записи, задачи
   выкатки (по влитым веткам задач между прошлой выкаткой и этой), словари и
   заготовка строк. Ничего не пишется.
2. Со строками через `--stdin` — проверка и вид будущих строк таблицы. Строка
   — `<задача или -> | <зона> | <тип> | <что изменилось>`. Каждая задача
   выкатки должна быть хотя бы в одной строке. Ничего не пишется.
3. С `--apply` — запись.

Время записи — момент запуска команды. Если коммит выкатки старше двух часов,
команда не гадает и просит выбрать: `--missed` — выкатка вышла раньше, время
берётся из коммита (у тега версии — из тега) с пометкой `≈`; `--now` — коммит
давний, а в прод вышел только что.

Откат — `kaiten release --rollback <версия> --reason "<почему>"`.

`--apply` требует включённого обновления Kaiten (`sync.kaiten`) и входа в
настройках: журнал пишут с машины, которой разрешено писать в Kaiten.

## Копия в теге и восстановление

Документ Kaiten пишется только целиком и без блокировки, а страница, открытая
в редакторе во время записи через API, может задвоиться (`docs/kaiten-api.md`,
«Документы»). Истории версий у правок через API нет. Поэтому:

- Запись целиком лежит ещё и в аннотации тега `released/<версия>`
  репозитория кода (у отката — `released/<версия>-rollback`). Тег ставится на
  выкаченный коммит и отправляется в origin **до** записи страницы. У
  `calendar` это и есть тег версии.
- Перед записью страница перечитывается и проверяется: одна таблица, шапка на
  месте, каждая строка читается, ничего лишнего. Не так — отказ; в
  повреждённую страницу команда не дописывает.
- `kaiten release --rebuild` возвращает на страницу строки своего репозитория
  из тегов. Строки, которые читаются, не теряются: задвоенные схлопываются,
  строки других репозиториев остаются. Если не читаются и они — та же команда
  из их репозитория.
- Kaiten отказал после отправки тега — команда говорит «запись сделана
  наполовину» и называет `--rebuild --apply`.
- Каждая запись заодно возвращает на страницу прежние записи своего
  репозитория, если их строки с неё пропали: открытый редактор может не
  задвоить страницу, а молча вернуть ей старое состояние — такая страница
  выглядит целой. `kaiten doctor` сверяет страницу с тегами и называет
  пропавшие записи.

Проверено живьём 19.11.2026: страница, созданная через API, принимает таблицу
и возвращает её дословно; открытие в редакторе пересохраняет страницу без
правок человека (таблица получает `size: fixed`, в конец ложится пустой абзац)
— формат это переживает; два символа, введённые в редакторе после записи через
API, задваивают страницу, и `--rebuild` возвращает её целой.

Имя `released/` занято инструментом: теги с этим началом, поставленные руками,
выкатку не записывают, а имя занимают.

## Сверка: выкатка без записи

Выкатку могут сделать в обход команды. Чтобы она не потерялась, ветка прода
сравнивается с записями:

- `kaiten start` отказывает, пока выкатка не записана, — первый, кто пришёл
  работать в репозиторий, дозаписывает её с `--missed`;
- `kaiten doctor` показывает то же и проверяет, что страница цела;
- сама `kaiten release` при нескольких выкатках без записи просит назвать,
  какую записать.

Работу держит только выкатка, которая вышла после начала журнала (первой
записи в этом репозитории) и старше двух часов. Свежую сейчас записывает тот,
кто её делал; всё, что было до начала журнала, — история, её заполняют без
спешки: `kaiten release --missed --version <версия>` (или `--commit <коммит>`),
начиная со старшей.

Откат без записи сверка видит, когда последний записанный релиз перестал быть
достижим из ветки прода (её вернули назад), — и требует `--rollback`. Откат
новым коммитом для сверки — обычная выкатка без записи: записать его как
откат решает тот, кто записывает.

Перед сверкой команда обновляет с сервера только ветку прода и теги записей;
сервер не ответил за 15 секунд — судит по тому, что уже есть в репозитории.

## Чего журнал не делает

- Не выкатывает и не пушит ветки: только тег записи.
- Не ждёт, пока прод обновится: время записи — момент запуска.
- Не чинит повреждённую страницу сам: восстановление — явная команда.
