# AGENTS.md

## Что это за репозиторий

Инструмент «задачи файлами в git ↔ Kaiten»: команда `kaiten` для
разработчиков и агентов, скилл агента, скрипты владельца проекта. Как устроено
— `README.md`; как ведёт себя API Kaiten — `docs/kaiten-api.md`. Агентский
MCP-сервер для не-разработчиков — `docs/agent-server.md`, код в
`src/agent-server/`.

Инструмент не знает ни одного проекта: всё о проекте лежит в `kaiten.json` его
репозитория задач, репозиторий кода подключается файлом `.kaiten`. Названия
проектов, людей, адреса и id живого аккаунта в этот репозиторий не попадают —
ни в код, ни в тесты, ни в документы, ни в сообщения коммитов (репозиторий
публичный). В тестах и примерах — нейтральные имена: Acme, Globex, alice, bob,
`PRJ-123`, `example.com`.

Стек: TypeScript + tsx + zod + vitest. Ничего лишнего: ни фреймворка, ни ORM.

## Правила

- **Ничего не пишем в Kaiten без `--apply`.** Сухой прогон — поведение по
  умолчанию у любой новой команды и скрипта, а не опция.
- **Мутации живого аккаунта — только после явного «да» владельца** на
  конкретный план: и массовые правки карточек, и структура.
- **Строгая типизация, `any` запрещён.** Ответы внешнего API разбираются через
  zod; схемы `passthrough()` и описывают только поля, которые мы читаем.
- **В тестах нет сети.** Клиент проверяется на поддельном `fetch`.
- **Токен не печатается никогда** — ни в логах, ни в отчётах, ни в URL.
- **Вывод `kaiten` не рассказывает о реализации**: ни путей хранилища, ни
  сырых ошибок git, ни стека. Ошибка — «что исправить в задаче». Справка
  команды — что она делает, аргументы, пример.
- **Отказ — лучше подсказки.** Агенты исполняют отказы команд и игнорируют
  подсказки, пришедшие после успеха: всё, что обязательно, проверяйте до
  записи.
- Комментарии и сообщения команд — по-русски.
- Формат коммита: `feat(kaiten-tracker): описание`, `fix(…)`, `docs(…)`.

## Чего не делаем

- Не двигаем файлы задач руками: перемещение `active/` ↔ `archive/YYYY-MM/`
  делают команды.
- Не строим синхронизацию на вебхуках: у Kaiten не опубликованы ни события,
  ни подпись, ни повторы. Сверка устойчива к потере события.
- Не даём агенту команд, которые подключают репозиторий или меняют поля,
  принадлежащие Kaiten (приоритет, исполнитель, сроки). Исключение —
  агентский сервер (`docs/agent-server.md`): при создании карточки он ставит
  ответственного (по умолчанию — самого человека); после создания
  ответственного, участников и сроки не меняет.

## Проверки перед коммитом

```bash
npm run typecheck && npm test
```

Многострочные правки на Windows — через редактор или node-скрипт, записанный
файлом: оболочка съедает обратные слэши и обратные кавычки в heredoc и
`node -e`.
