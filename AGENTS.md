# AGENTS.md

## Что это за репозиторий

Синхронизатор задач «файлы в git ↔ Kaiten». Отдельный репозиторий по решению Q17
эпика `reports`, который живёт в
`../acme-app/tasks/backlog/epics/20260916_epic_p1_reports/`.
**Решения Q1–Q35 в карточке эпика — источник истины по архитектуре.** Прежде чем
предлагать другую схему владения полями, другой ключ или вебхуки вместо цикла
сверки, прочитайте их: почти всё уже разобрано и решено с владельцем.

Стек: TypeScript + tsx + zod + vitest. Ничего лишнего: ни фреймворка, ни ORM.

## Правила

- **Ничего не пишем в Kaiten без `--apply`.** Dry-run — поведение по умолчанию у
  любой новой команды, а не опция.
- **Мутации живого аккаунта — только после явного «да» владельца.** Это относится
  и к заливке, и к массовым обновлениям карточек.
- **Строгая типизация, `any` запрещён.** Ответы внешнего API разбираются через
  zod; схемы `passthrough()` и описывают только те поля, которые мы читаем —
  структура карточки Kaiten задокументирована не целиком.
- **В тестах нет сети.** Клиент проверяется на поддельном `fetch`.
- **Токен не печатается никогда** — ни в логах, ни в отчётах, ни в URL.
- Комментарии и сообщения коммитов — по-русски, как в основном репозитории.
- Формат коммита: `feat(slug): описание`, `fix(slug): …`, `docs(slug): …`.

## Чего в этом репозитории не делаем

- Не редактируем файлы задач в других репозиториях: заливка читает их, но не
  меняет. Обратная запись (`tracker: PRJ-123` в шапку) появится только вместе с
  форматом задач v2 — это отдельная story в эпике.
- Не тащим в Kaiten `LOG.md` и вложения: они остаются в git, в карточке остаётся
  ссылка.
- Не строим синхронизацию на вебхуках: у Kaiten не опубликованы ни список
  исходящих событий, ни подпись, ни ретраи (проверено 23.09.2026). Цикл сверки
  устойчив к потере события по определению.
